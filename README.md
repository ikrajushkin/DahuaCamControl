# DahuaCamControl

Локальное Windows-приложение (Python + tkinter) для управления въездными воротами
через камеры Dahua с распознаванием автомобильных номеров (ANPR).

## Возможности

- **1 или 2 камеры**: вторая панель появляется автоматически, если в конфиге заполнены
  её креды (ip/username/password);
- **live-видео** каждой камеры (MJPEG-поток `/cgi-bin/mjpg/video.cgi` — без ffmpeg/VLC);
- **кнопка «ОТКРЫТЬ ВОРОТА»** на каждой панели (`trafficSnap.cgi?action=openStrobe`,
  раздел 10.4.1 HTTP API Dahua V3.52);
- **фото последнего распознанного автомобиля** под видео (размер настраивается
  `video.photo_scale`, по умолчанию вдвое меньше видео);
- **крупная строка с распознанным номером** + метка сверки по БД самой камеры:
  «ЕСТЬ в справочнике камеры» / «НЕТ в справочнике камеры» / «ЗАПРЕЩЁН
  (блок-лист камеры)» / «справочник камеры недоступен» (сравнение
  нечувствительно к регистру, кириллица↔латиница);
- **БД номеров камер — только чтение**: приложение НИКОГДА не изменяет
  справочники камер (AllowListDB/BlockListDB) и не ведёт собственного списка
  номеров. Решение об открытии принимает камера либо оператор кнопкой
  «ОТКРЫТЬ ВОРОТА»;
- **справочник камер — справа от видеопотоков**, узкой колонкой (чуть больше
  максимальной длины номера), только чтение;
- **журнал событий** (ANPR и открытия ворот) — под панелями камер, на всю их
  ширину; продублирован в файле `gate_log.jsonl`.

ANPR-события принимаются подпиской `snapManager.cgi?action=attachFileProc`
(разделы 4.4.3 и 10.1 API): multipart-ответ содержит текстовые части с полями
`Events[...].TrafficCar.PlateNumber=...` и JPEG-снимок автомобиля.

## Установка

```bat
python -m pip install -r requirements.txt
copy config.example.json config.json
:: отредактируйте config.json: ip/username/password камеры 1 (обязательно)
:: и камеры 2 (опционально — панель появится только при заполненных кредах)
python app.py
```

Зависимости: Python 3.10+ (tkinter включён), `requests`, `Pillow`.
Никаких дополнительных кодеков не требуется — видео приходит JPEG-кадрами по HTTP.

## Конфигурация (config.json)

| Ключ | Назначение |
|---|---|
| `cameras` | массив из 2 камер: `name`, `ip`, `username`, `password`, `channel` (с 1). Камера отображается, только если заполнены ip/username/password |
| `video.width/height` | размер окна видео в GUI (фото авто — пропорционально `video.photo_scale`). Это ТОЛЬКО масштаб отображения: реальное разрешение картинки определяется потоком камеры |
| `video.photo_scale` | размер фото авто под видео относительно самого видео: `0.5` — вдвое меньше (по умолчанию), `1.0` — в размер видео (или промежуточно, например `0.75`). Допустимый диапазон 0.25..1.0; значения вне его приводятся к границам. Если окно не влезает в экран, фото уменьшается вместе с видео |
| `video.mode` | `snapshot` (по умолчанию) — опрос снимков `snapshot.cgi`: каждый кадр отдельный короткий HTTP-запрос (поток не «замерзает»), снимок берётся с матрицы в полном разрешении канала независимо от подпотоков; `stream` — MJPEG-поток `mjpg/video.cgi` (больше FPS, но длинное соединение может подолгу не отдавать кадры и подпоток обычно зернистый) |
| `video.interval` | период опроса снимков в режиме `snapshot`, сек (по умолчанию 0.4 ≈ 2.5 FPS) |
| `video.subtype` | только для `stream`: какой поток камеры забирать: 0 — основной (обычно максимальное разрешение), 1 — подпоток 1 (обычно D1/720P — низкое разрешение), 2 — подпоток 2 |
| `video.set_resolution` | только для `stream`. Если заполнен (например `"1920x1080"` или `"720P"`), приложение само поменяет разрешение выбранного потока НА КАМЕРЕ (`Encode[…].Video.VideoResolution` через `configManager.cgi?action=setConfig`). Пусто — настройки камеры не трогаются. Внимание: менять основной поток не рекомендуется, если камеру смотрят другие потребители |
| `anpr_events` | коды событий для подписки (по умолчанию `TrafficJunction`) |
| `heartbeat` | интервал heartbeat подписки событий, сек |
| `camera_whitelist` | периодическое ЧТЕНИЕ БД номеров камер: `enable` (по умолчанию `true`) и `sync_interval`, сек (по умолчанию 300; `0` — один раз при запуске). Чтение через `recordFinder.cgi` (таблицы `TrafficRedList`/`TrafficBlackList`, раздел 10.3.4) с авто-фолбэком на JSON API `VehicleRegisterDB`. Только чтение: ничего в справочники камер не пишется |
| `log_file` | файл журнала (JSONL) |

## Сборка standalone exe

Можно собрать автономный exe — запуск на любой Windows-машине без установки
Python и библиотек (tkinter, requests, Pillow упаковываются внутрь):

```bat
python -m pip install pyinstaller
python -m PyInstaller --noconfirm --clean --onefile --windowed ^
  --name DahuaCamControl --hidden-import config --hidden-import gui ^
  --hidden-import dahua_client app.py
```

Готовый файл: `dist\DahuaCamControl.exe` (~30 МБ).

**Важно про данные:** в собранной версии все файлы данных — `config.json`,
`gate_log.jsonl`, `debug.log` — создаются и читаются
в папке самого exe (не в `%TEMP%`, не в профиле пользователя). Положите exe
в отдельную папку, запустите один раз — появится шаблон `config.json`;
заполните ip/username/password и перезапустите.

Антивирусы иногда ругаются на onefile-сборки PyInstaller (SmartScreen) —
это ложное срабатывание, характерное для неподписанных exe; при необходимости
используйте вариант `--onedir` (папка `dist\DahuaCamControl\` с exe и dll).

## Логирование

| Файл | Что содержит |
|---|---|
| `gate_log.jsonl` | журнал событий: ANPR-распознавания (`type: "anpr"` — номер, камера, решение по БД камеры, код события, сырые поля) и открытия ворот (`type: "gate_open"` — камера, успех, номер) |
| `debug.log` | диагностический журнал приложения |
| окно приложения | то же, что в `gate_log.jsonl` (гуманно: номера, метки сверки, ошибки открытия ворот) + статусы воркеров |

`debug.log` пишется всегда, но в минимальном объёме: запуск приложения,
создание шаблона конфигурации, ошибки (сеть, открытие ворот, запись логов),
подключения/переподключения воркеров видео и ANPR. Полный режим включается
запуском с флагом `--debug`: дополнительно пишутся сырые поля каждого ANPR-
события и ежеминутный статус потоков (`watchdog`). При зависаниях «нечего
показать» — пришлите `debug.log`: по нему видно, подключался ли воркер
к камере и на каком шаге остановился.

## Проверка без камеры

```bat
python selftest.py
```

12 офлайн-проверок: нормализация номеров, решение по БД камеры, разбор таблиц
`recordFinder`, multipart-парсер (MJPEG и attachFileProc), извлечение номера,
работа с изображениями, размеры фото (`video.photo_scale`), конфиг.

Для диагностики выгрузки справочника с камеры (только чтение):

```bat
python check_db.py --ip IP --username ЛОГИН --password ПАРОЛЬ
```

## Структура проекта

| Файл | Назначение |
|---|---|
| `app.py` | точка входа (запуск GUI) |
| `gui.py` | интерфейс: панели камер, журнал, просмотр справочника камеры (чтение) |
| `dahua_client.py` | клиент HTTP API Dahua (Digest-аутентификация), multipart-парсер, фоновые потоки видео/ANPR/чтения БД |
| `config.py` | загрузка/сохранение конфига, решение по БД камеры, JSONL-лог |
| `check_db.py` | диагностика чтения БД номеров камеры (группы, записи) без изменений |
| `main.py` | консольный прототип (исторический, сохранён как есть) |
| `swagger.yaml` | OpenAPI-спецификация серверной версии (историческая) |
| `DAHUA_HTTP_API V3.52 for BITRU.pdf` | полная документация API экосистемы Dahua |

## Если справочник камеры не подгружается

Метка «справочник камеры недоступен» или «НЕТ в справочнике камеры» при
заведомо известных номерах — метка показывает причину прямо в GUI, а подробности
лежат в `debug.log` (строки `[camera] ... recordFinder` и `findGroup`). Приложение
повторяет попытку чтения каждые ~30 секунд, поэтому после исправления причины
справочник подгружается сам, без перезапуска:

- **HTTP 403: Authority:check failure** — учётной записи не выданы права на
  БД номеров (ANPR). В веб-интерфейсе камеры (Настройки → Аккаунт → права)
  выдайте пользователю права администратора или права на «Интеллектуальные
  функции/ANPR», либо используйте учётную запись администратора;
- **HTTP 400: Bad Request** — на части прошивок (например `5.004.0000000.1.R`
  у ITC413) весь JSON-слой `/cgi-bin/api/*` отклоняет любые запросы с 400
  независимо от учётной записи — это НЕ вопрос прав администратора. Приложение
  в этом случае автоматически читает справочник запасным каналом
  `recordFinder.cgi` (раздел 10.3.4, таблицы `TrafficRedList`/`TrafficBlackList`),
  поэтому сверка работает; если же метка всё равно «справочник камеры
  недоступен» — оба канала не отвечают, смотрите `debug.log`;
- **HTTP 401 / сеть** — проверьте ip/username/password в `config.json`.

Подробную картину покажет диагностика (только чтение, ничего не изменяет):

```bat
python check_db.py --ip 192.168.82.11 --username WevoUser --password ПАРОЛЬ
```

## Известные ограничения

- MJPEG-подпоток камеры даёт ~5–15 FPS; для 25 FPS основного потока нужен RTSP
  (ffmpeg/OpenCV) — в этой версии не используется намеренно (нулевые внешние
  зависимости медиа-стека);
- при незаполненных кредах камера пропускается (приложение работает с одной камерой);
- секреты хранятся в `config.json` локально (в .gitignore). Не публикуйте его.
